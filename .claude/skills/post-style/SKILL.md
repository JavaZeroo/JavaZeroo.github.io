读者是「手边开着论文、想把每个模块看懂」的人，有本科线性代数基础。文章可以到 8k 字，篇幅换深度。

## 每一节的骨架

1. **动机先行**：小节开头交代「为什么突然讲这个」，上一节的哪个问题把读者带到这里。结论先行、动机缺席的小节是返工的主因。
2. **从目标函数推公式**：先写问题，再写目标函数，一步步推到递推式或最终形式。只列结果不算讲了。
3. **先结论、后推导、推导折叠**：超过五步的推导，正文直接给目标公式（加框、编号），把完整推导放进 `:::details[标题]`。折叠里**不跳步**，每一步写明用了什么性质（结合律、对角阵性质、归纳法）。
4. **核心公式前先回顾依赖**：用到上一篇的公式时，把它连同图解摆出来再往下走。
5. **每个数字接一个后果**：给出一个维度、一个比例、一个 FLOPs 之后，写它带来什么（省了多少、卡在哪、为什么选这个）。数字要能对回 config.json 或论文的表；论文没给的量（并行度、GPU 数）留作变量，不要编。
6. **定义先说不是什么**：引入新概念时先划掉容易混淆的邻居，再给定义。
7. **实验证据紧跟设计选择**：消融或合成任务放在它支持的那个决定后面，并说明「这个任务考的是什么能力」。

## 谱系与总览

- 模型谱系用**流程图**讲演化：每条边标「加了什么」，允许分叉与汇合，节点可点跳到对应 h3。表格只做末尾总结。
- 总览、速览、谱系类文章：**一个机制一个 h2 一张图**，每节回答同一组固定问题（切什么 / 为什么能切 / 前向反向各有什么通信 / 通信量 / 计算与显存），末尾讲主流框架怎么表达同一套东西。
- 标题写清「讲什么」：「并行策略总览：六个维度各切什么、怎么通信」。意象式标题（「谁在等谁」）不用作文章或小节标题，可以作为正文里的教学线索。

## 通用知识与模型连载的边界

写模型拆解时，每一段先问：**这是这篇论文的贡献，还是背景知识？**

- 背景知识（并行策略、ZeRO、注意力基础、优化器、流水线调度……）写进「大模型笔记」专栏（series `llm`）对应章节：架构 / 并行 / 训练框架工程 / 性能优化。
- 模型连载只留该模型自己的改动，背景一句话带过并链接到 llm 专栏那篇。
- 动笔前 `grep` 一下 `src/content/posts/llm-*.mdx` 与各系列，已有的只引用不重写。

## 形式

- 中文写作，术语保留英文原文；公式 `$...$` / `$$...$$`，块级公式用 `\tag{n}` 编号并与论文编号对齐，论文没有的用自己的连续编号。
- 提示框 `:::note{type="info"|"warning"}`；折叠 `:::details[标题]`。
- 站内链接写绝对路径 `/YYYY/MM/DD/<文件名>/`，日期取目标文章的 `pubDate`。
- 每篇开头一段说明对应论文的哪一节、这篇讲到哪里；连载文章在开头放总架构图并 `highlight` 本篇模块。
- 论文没写、只在代码或 config 里的细节要单独标出；自己补的推理要标「这是我的解读」。
