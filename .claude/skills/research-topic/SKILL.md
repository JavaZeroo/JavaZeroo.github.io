参数：主题、目标专栏目录（如 `drafts/llm-perf`）。产出是**写作原材料**，不是正文，不设计文章结构。适合交给子代理并行跑多个主题。

## 必须做的事

1. **找到一手资料并真正读**：论文用 arXiv 原文（`https://arxiv.org/abs/<id>` 与 `/pdf/<id>`），代码用 GitHub 原文件（raw URL，或在 scratchpad `git clone --depth 1` 后 grep/sed）。公式与代码行为不凭记忆写，每条关键结论指到出处：论文章节/公式编号，或文件路径+函数名。
2. **公式从动机推到结果**：记录论文推导的每一步，缺的自己补并标「补」。
3. **代码落到具体文件**：仓库、commit 或版本、路径、函数名、关键几行摘录（每处 ≤ 30 行）。
4. **数字有来源**：显存省多少、加速多少、误差多大，都标出处与实验条件。
5. **记下常见误解**：网上流传但与一手资料不符的说法。
6. **给图的建议**：最该画的 1–3 张图，各自要表达的机制（只写，不画）。
7. **查已有文章**：`grep` `src/content/posts/llm-*.mdx`、`kimi-k3-*.mdx`、`deepseek-v4-*.mdx`，第 6 节写清哪些概念已讲过只需引用、哪些留给别的文章。边界规则见 skill `post-style`。

## 输出格式

写到 `drafts/<专栏>/refs/<主题>.md`，结构固定：

```
# <题目>
## 0. 一句话：这篇要解决什么问题
## 1. 一手资料清单（URL + 版本/commit + 读了哪些部分）
## 2. 核心机制与推导（分小节，公式完整，标出处）
## 3. 代码落点（仓库/路径/函数，摘录，解释）
## 4. 关键数字（表格：数字 / 条件 / 出处）
## 5. 常见误解与澄清
## 6. 与本专栏其他文章的接口
## 7. 图的建议
## 8. 待确认 / 没查到的点
```

中文，术语保留英文。篇幅不限，宁多勿少，但每条都要有出处。完成标准：第 2、3、4 节每一条都能指到第 1 节里的某个资料。
