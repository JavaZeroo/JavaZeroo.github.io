DSA（DeepSeek Sparse Attention）首次随 **2025-09-29 的 V3.2-Exp** 发布，正式 V3.2 沿用。核心思路：**先用便宜的索引器找位置，再让昂贵的主注意力只计算这些位置。**[发布公告](https://www.deepseek.com/en/news/v3-2-exp/)

本文对应[报告 §2.1–2.3](https://arxiv.org/html/2512.02556v1#S2.SS1)。下面的数学推演是我的解读，用来解释设计选择，不代表作者真实的研究顺序。

## 1. 把全量扫描交给小索引器

长上下文里，每个 query 都扫描完整主 KV 太贵。DSA 增加一条更便宜的打分路径：

<DsaFlow />

**索引器负责选谁；主注意力仍计算自己的权重。** 只保留哪些位置，才能尽量不损伤输出？

## 2. 从输出误差推到共享 top-k

对固定 query、固定注意力头，原输出是 $u=\sum_s a_s v_s$。丢弃的注意力概率质量记为 $\varepsilon$；在保留集合上重新归一化，得到 $\widetilde u$。若 $\lVert v_s\rVert\le M$，则：

$$
\boxed{\lVert u-\widetilde u\rVert\le 2M\varepsilon.}
\tag{A}
$$

因此，**固定只看 $k$ 个位置时，尽量少丢概率质量**是一个有数学依据的代理目标。拖动下图，或故意漏掉最大项：

<AttentionMassDemo />

:::details[误差界的三步推导]
设保留集合非空，$0<\varepsilon<1$，丢弃部分归一化后的输出为 $u_{\rm drop}$。保持同一组 Q、K、V：

$$
\begin{aligned}
u&=(1-\varepsilon)\widetilde u+\varepsilon u_{\rm drop},\\
u-\widetilde u&=\varepsilon(u_{\rm drop}-\widetilde u),\\
\lVert u-\widetilde u\rVert
&\le\varepsilon(\lVert u_{\rm drop}\rVert+\lVert\widetilde u\rVert)
\le2M\varepsilon.
\end{aligned}
$$

最后一步用了凸组合与三角不等式；$\varepsilon=0$ 时误差为零。它是单头输出的最坏界，不保证最终模型答案的误差。
:::

DSA 让各主注意力头**共享一份下标**，便于复用 KV 读取。于是把各头 softmax 后的概率取平均，选平均概率的 top-k：

<SharedSelection />

因为平均丢弃质量恰好是 $1-\sum_{s\in\mathcal S}p_s$，这个选择能使它最小。这里平均的是**概率，不是原始 QK 分数**。不同头的实际任务贡献未必等权，后面仍需继续训练。

## 3. 用低维打分预测位置，用 ReLU 保留多种响应

精确的注意力概率要先算完整主注意力，成本已经付出。于是用小模型预测它。官方 lightning indexer 的打分为：

$$
\boxed{I_{t,s}=\sum_{j=1}^{H^I}w^I_{t,j}\,
\operatorname{ReLU}\!\left((q^I_{t,j})^\top k^I_s\right).}
\tag{1}
$$

**64 个索引 query 头、每头 128 维，共享一个 key；不做 value 聚合。** 它只需输出排序分数。实际取 $k=2048$，这些宽度和预算来自实验配置，不能由误差界唯一推出。[官方配置](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp/blob/87e509a2e5a100d221c97df52c6e8be7835f0057/inference/config_671B_v3.2.json)

为什么逐头加 ReLU？没有非线性，多头加权可以合成一个 query：$\sum_j w_j q_j^\top k=(\sum_j w_j q_j)^\top k$。下面用一维例子看区别：

<DsaRelu />

论文明确说选择 ReLU 考虑了吞吐；图中解释的是非线性的作用，并不说明 ReLU 是唯一选择。权重 $w$ 随当前 query 变化，且可以为负，因此索引分数也可以为负。[报告公式 (1)](https://arxiv.org/html/2512.02556v1#S2.SS1)、[官方 `Indexer`](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp/blob/87e509a2e5a100d221c97df52c6e8be7835f0057/inference/model.py#L435-L487)

## 4. 用注意力概率教索引器，绕开离散选择的梯度

top-k 返回整数下标，普通反向传播无法通过下标学会排序。DSA 把主注意力当教师：令 $p$ 为按头平均的概率，$r=\operatorname{softmax}(I)$，训练索引器拟合它。

$$
\mathcal L^I=\sum_t D_{\rm KL}(p_{t,:}\|r_{t,:}),
\qquad
\frac{\partial D_{\rm KL}(p\|r)}{\partial I_s}=r_s-p_s.
\tag{3}
$$

前半是论文的目标，后半是把教师视为常量时的梯度：**低估重要位置，就抬高它的分数。**

<DsaKl />

推理时直接对 $I$ 取 top-k 即可；softmax 不改变排序。

:::details[拟合概率为什么有助于选对位置？]
这是补充推导。记 $\mathcal S^\star=\operatorname{TopK}(p)$，$\widehat{\mathcal S}=\operatorname{TopK}(r)$，$p(A)=\sum_{s\in A}p_s$。预测集合在 $r$ 下最优，所以 $r(\mathcal S^\star)\le r(\widehat{\mathcal S})$。加减这两项：

$$
\begin{aligned}
p(\mathcal S^\star)-p(\widehat{\mathcal S})
&\le(p-r)(\mathcal S^\star)+(r-p)(\widehat{\mathcal S})\\
&\le\lVert p-r\rVert_1
\le\sqrt{2D_{\rm KL}(p\|r)}.
\end{aligned}
\tag{B}
$$

第二步用了每个集合的概率差不超过 $\frac12\lVert p-r\rVert_1$，最后一步是 Pinsker 不等式（自然对数）。约束的是**保留质量的差距**，不是下标必须完全相同；也只适用于完整历史上的分布。
:::

## 5. 先训练索引器，再让主模型适应稀疏输入

随机索引器会漏掉重要上下文，所以先保持主模型稠密、冻结参数，单独热身索引器；再启用 top-k。起点是已扩展到 128K 的 V3.1-Terminus base。[报告 §2.1.1](https://arxiv.org/html/2512.02556v1#S2.SS1.SSS1)

<DsaTraining />

稀疏阶段的教师来自**当前选中集合内**的主注意力，概率在集合内归一化：

$$
\mathcal L^I=\sum_t D_{\rm KL}\!\left(
p^{\mathcal S}_{t,:}\,\middle\|\,
\operatorname{softmax}(I_{t,\mathcal S_t})\right).
\tag{4}
$$

这样不用额外跑完整的 dense 教师。但集合外没有直接监督，**集合内 KL 很小，也可能漏选重要位置**。

工程上最重要的是分开两条梯度：**LM 损失只更新主模型，KL 只更新索引器**。索引器的输入（包括共享 query latent）和教师概率都要 `detach`，主注意力本身仍需反向传播。

:::details[训练规模与最小代码]
官方全局训练规模；128K 指 131072 token：

| 阶段 | 步数 × 每步序列数 × 长度 | 学习率 |
|---|---|---|
| 稠密热身 | $1000\times16\times128\mathrm K$，约 2.1B token | $10^{-3}$ |
| 稀疏训练 | $15000\times480\times128\mathrm K$，约 943.7B token | $7.3\times10^{-6}$ |

每步序列数是全局规模，不是单卡 batch。以下为教学伪代码，展示梯度边界：

```python title="稀疏训练：两组参数接收各自的梯度"
I = indexer(h.detach(), query_latent.detach())
selected = causal_topk(I)                 # 下标不传梯度
attention, logits = main_attention(selected)
p = attention.detach().mean(dim=head_axis)

loss_lm = lm_loss(logits, targets)
loss_index = kl_on_selected(I, p, selected)
main_optimizer.zero_grad()
index_optimizer.zero_grad()
(loss_lm + loss_index).backward()
main_optimizer.step()
index_optimizer.step()
```

[完整 CPU 示例](/files/dsa/dsa_training_demo.py)可运行 `python dsa_training_demo.py --check-only`，检查因果性、概率归一化、梯度隔离与 $k=N$ 等价性。它使用小型 MQA 和稠密矩阵模拟选择，不用于证明生产加速。
:::

:::details[扩到 128K，工程实现要守住哪些条件？]
下面是按公开目标推导的实现要求；官方未公布完整训练器。

- **分块而非保存完整矩阵。** 一个 128K × 128K 的 FP32 矩阵就占 64 GiB。热身教师可先求全局 log-sum-exp，再按块重算概率、累计 KL；不能把每个 key 块单独 softmax 后拼起来。
- **选择范围必须正确。** top-k 前屏蔽未来和其他 packed 样本；合法位置不足 $k$ 时，gather 后也要屏蔽无效项。
- **前后向都要稀疏。** 按下标读 KV，反向正确累加多个 query 对同一 K/V 的梯度。全量计算后再加 mask，表达了稀疏语义，却没省掉打分计算。
- **验证全局召回。** 除集合内 KL，还要在小验证集重算 dense 教师，测保留质量，并检查长上下文任务与实际步时。

V3.2 的索引 query 复用主模型的 1536 维 query latent。索引 Q/K 经 RoPE、正交 Hadamard 旋转后量化到 FP8；旋转在精确算术下保持点积，量化仍有误差。打分累加、ReLU 和头加权使用 FP32。索引器与主 MLA 的 RoPE 布局不同，不能直接互换。[官方实现](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp/blob/87e509a2e5a100d221c97df52c6e8be7835f0057/inference/model.py#L428-L612)、[FP8 kernel](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp/blob/87e509a2e5a100d221c97df52c6e8be7835f0057/inference/kernel.py#L199-L277)
:::

## 6. 计算和读取减少，缓存仍保留

每次选中的位置不同，未选 token 下次还可能用到，所以主 KV 不能删除。加上索引缓存后，**容量反而增加**：

<DsaCost />

图按[官方配置](https://github.com/deepseek-ai/DeepSeek-V3.2-Exp/blob/87e509a2e5a100d221c97df52c6e8be7835f0057/inference/config_671B_v3.2.json)与 [FlashMLA 的 V3.2 缓存格式](https://github.com/deepseek-ai/FlashMLA/blob/ba89a3466e9470ad08ab39738d4e7bb66989e1e7/docs/20250929-hopper-fp8-sparse-deep-dive.md)推算。主注意力从 128K 选到 2K，只表示单 query 的主 KV 条目少了 64 倍，不能当作整体加速比。索引器仍全量扫描，整个 prefill 仍含二次复杂度。

:::details[图中数字怎么算？]
固定 MQA 吸收形式：主 query 128 头，QK 为 576 维、value 为 512 维；乘加计 2 FLOPs。$N=131072$，$k=2048$：

$$
\begin{aligned}
F_{\rm dense}&=2\times128\times(576+512)N,\\
F_{\rm DSA}&=2\times128\times(576+512)k
+2\times64\times128N.
\end{aligned}
$$

一条 FP8 主 KV 为 $512+4\times4+64\times2=656$ 字节；额外索引为 $128+4=132$ 字节。理想读取量从 $656N$ 变为 $656k+132N$；缓存容量从 $656N$ 变为 $(656+132)N$。未计页面对齐、重复加载及其他模块。
:::

使用已训练好的 V3.2 时，应用层照常输入文本，兼容的推理引擎在模型内部执行选择。给自己的 dense 模型加入 DSA，则要完成**索引器热身 → 稀疏继续训练 → 接入匹配的稀疏 kernel**。长上下文更值得这样做；短序列的索引和 top-k 开销可能抵消收益。
