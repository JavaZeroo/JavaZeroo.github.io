Kimi K3 模型结构（11）：从推理代码看 K3.1 Pro 的 Gated DSA

沿 Hugging Face 配置、vLLM 和 SGLang 的推理实现拆解 Kimi K3.1 Pro：69 层 KDA 与 24 层 Gated DSA 如何混合，32 头索引器怎样选出 top-2048，NoPE、输出门、两份缓存和每层独立索引分别落在哪里。

这一篇补充 Kimi K3.1 Pro 的结构。前面的 K3 连载按技术报告展开，这次换成从推理代码往回读：以发布 checkpoint 的 config.json 确定维度，以 vLLM 的 K3.1 实现恢复前向计算，再用 SGLang 交叉核对。

先给结论：K3.1 Pro 仍是 KDA 与 MLA 家族注意力交替的混合 MoE。最明确的结构变化，是把原来 24 层 Gated MLA 改成 Gated DSA：先用一个小索引器选历史 token，再让 MLA 只对选中的位置做注意力，最后仍乘 sigmoid 输出门。 69 层 KDA、Attention Residuals、Stable LatentMoE 和 MoonViT-V2 的结构配置都沿用 K3。发布配置与官方模型卡能直接对上这个结论。

索引器用三路投影，决定当前 token 读哪些历史位置

K3 的 MLA 每次要对全部可见历史做注意力。历史长度到 1M 时，即使 KV 已经压到低维，逐条读取和计算仍很贵。DSA（DeepSeek Sparse Attention）的处理是先做一次较便宜的打分，只把高分位置交给主注意力。

这个打分器叫 indexer，索引器。它选择的是历史 token 的位置。与 DeepSeek-V4 的 CSA不同，这里没有先把多个 token 压成一个时间块再选择。

令 xt∈R7168x_t\in\mathbb R^{7168}xt​∈R7168 表示本层送入注意力的隐藏态。索引器有三路输入变换，下面按 vLLM 的 KimiK3DSAIndexer 展开。

Query 从主注意力已经算好的低秩表示分出

先回顾 MLA 的 query：它先下投影到 1536 维，做 RMSNorm，再展开到各个主注意力头。索引器复用前半段：

ctQ=RMSNorm⁡(Wqaxt)∈R1536,qtI=reshape⁡32×128(WqIctQ).(2)c_t^Q=\operatorname{RMSNorm}(W_q^a x_t)\in\mathbb R^{1536}, \qquad q_t^I=\operatorname{reshape}_{32\times128}(W_q^I c_t^Q). \tag{2}ctQ​=RMSNorm(Wqa​xt​)∈R1536,qtI​=reshape32×128​(WqI​ctQ​).(2)

主注意力的 WqbW_q^bWqb​ 把同一个 ctQc_t^QctQ​ 展开成 96×19296\times19296×192，索引器的 WqIW_q^IWqI​ 则展开成 32×12832\times12832×128。两者共用 query latent，各有自己的上投影。不能把 32 个索引头算进主注意力的 96 个头里。

Key 是每个 token 一条 128 维向量

索引器的 key 直接从 xsx_sxs​ 投影，不从主 MLA 的 512 维 KV latent 取：

ksI=LayerNorm⁡(WkIxs)∈R128.(3)k_s^I=\operatorname{LayerNorm}(W_k^I x_s)\in\mathbb R^{128}. \tag{3}ksI​=LayerNorm(WkI​xs​)∈R128.(3)

32 个索引头共用这条 key，因此历史缓存每个 token 只增加一条 128 维索引 key，而不是 32×12832\times12832×128 个数。它与 MLA 的主 KV 是两套投影、两份缓存。

这里用的是带增益和偏置的 LayerNorm。vLLM 的 KimiK3DSAIndexerKNorm.forward 在 FP32 中做归一化，再转回输入 dtype；SGLang 的 _init_dsa 也明确要求 index_k_norm_type="layernorm"。不要因为主干大量使用 RMSNorm，就把索引 key 的归一化也写成 RMSNorm。vLLM 实现、SGLang 配置

每个索引头还有一个输入相关的权重

第三路投影给出 32 个标量：

at=WaIxt∈R32.(4)a_t=W_a^I x_t\in\mathbb R^{32}. \tag{4}at​=WaI​xt​∈R32.(4)

这些权重没有经过 sigmoid，也没有经过 softmax，可以为负。代码中的 weights_proj 或 “head gate” 指的是这一路，和稍后讲的 12288 维 sigmoid 输出门是两件事。SGLang 的 head weight 处理

点积经过 ReLU 后按头求和，再取 top-2048

三路投影得到的是小 query、历史小 key，以及各头权重。下一步需要把 32 个头对同一个历史 token 的判断合成一个分数。

忽略低精度量化与中间舍入，代码对应的打分可以写成：

在可见历史中选出位置集合：

正文的 ttt 从 1 开始，包含当前 token。每个 query 得到一组位置，本层所有 96 个主注意力头共用这一组位置，然后各自计算真正的注意力分布。不同 query 可以选不同位置，不同 DSA 层也可以选不同位置。

如果可见历史不足 2048 条，就没有必要丢弃任何位置。SGLang 的 _should_skip_logits_computation 在适用的执行路径上会直接跳过打分，让后续使用全部有效位置。这是短上下文下的等价优化，不是又多了一种模型层。代码

NoPE 要看实际开关。 发布配置同时设置 mla_use_nope=true 和 index_rope_dim=0，所以主 MLA 与索引器都不做 RoPE。主注意力里的 qk_rope_head_dim=64 仍然保留：它代表 64 维共享 key 分量，并不代表执行了旋转。SGLang 还为 K3.1 设置 index_apply_hadamard=false，不能把 DeepSeek 通用索引器的默认预处理原样套过来。配置、SGLang 适配

选出位置以后，仍然是带输出门的 MLA

索引分数只负责选择位置。接下来使用的是主 MLA 自己的 query、key、value，重新计算 softmax；索引器的分数不会直接拿来加权主 value。

推理时，MLA 可以把 WhKW^K_hWhK​ 吸收到 query 一侧，在低维 latent 上完成计算，再恢复各头 value 输出。稀疏化没有要求显式展开所有历史 K/V。这里把展开式写出来，是为了看清楚：DSA 限制的是注意力访问的历史位置，MLA 压缩的是每个位置的 KV 表示，Gated 控制的是注意力输出。

共享 top-k 工作缓冲，不是跨层共享选择结果

vLLM 在模型级分配了一个 topk_indices_buffer，依次交给各个 DSA 层使用。这个 buffer 共享的是临时存储空间：一层计算完之后，下一层可以覆盖同一块内存。

模型本身设置 index_topk_freq=1。vLLM 与 SGLang 都拒绝把 K3.1 配成其他频率，并明确说明每个 DSA 层运行自己的 indexer。因此不能看到共享 buffer，就把它解释成 DeepSeek-V4.1 的 Reuse 那样跨层复用 top-k。配置里的 index_skip_topk_offset 也不能单独用来推断有索引复用。vLLM、SGLang

把推理优化拿掉后，索引部分可以用下面这段说明性伪代码表示。它省略量化、页面映射、并行和舍入，不是可直接加载 checkpoint 的实现：

一个 query 的逻辑前向；省略量化与并行python
# x: [7168]，q_latent 同时供主 MLA 和索引器使用
q_latent = q_rmsnorm(q_a_proj(x))                 # [1536]
index_q = index_wq(q_latent).reshape(32, 128)
index_k = index_layernorm(index_wk(x))             # [128]
head_weights = index_weights_proj(x)              # [32]，无 sigmoid

index_cache.append(index_k)                       # 先包含当前位置
per_head = relu(index_q @ index_cache.T)           # [32, t]
scores = (head_weights[:, None] * per_head).sum(0)
scores = scores / sqrt(32 * 128)
selected = topk_indices(scores, min(2048, len(scores)))

# 主 KV 也已写入当前位置；sparse_mla 内使用主 Q/K 的 softmax
z = sparse_mla(q_latent, main_kv_cache, selected)  # [96 * 128]
y = o_proj(z * sigmoid(g_proj(x)))                # [7168]

稀疏化减少主注意力读取量，缓存仍随历史增长

理解了选择流程，就可以回答两个实际问题：省掉了什么计算，又需要存什么。

首先，top-2048 不是缓存容量。 今天这个 query 没选中的历史位置，下一步可能被选中。DSA 仍要保存全部可用历史的主 KV，以及用来重新打分的索引 key。

在每个 DSA 层，逻辑内容是：

持久状态每个 token 的逻辑内容用途
主 MLA cache512 维 latent + 64 维共享 key读取被选中位置，计算主注意力
indexer cache128 维共享 key给历史位置打分
top-k 工作缓冲每个当前 query 最多 2048 个位置编号本次计算使用；不是历史内容的替代品

如果只比较结构，假设所有缓存数都用 BF16，原 K3 的 24 层 MLA 在 1M 历史下需要 24×576×2×1048576=2724\times576\times2\times1048576=2724×576×2×1048576=27 GiB；K3.1 增加索引 key 后，同一假设下是 24×(576+128)×2×1048576=3324\times(576+128)\times2\times1048576=3324×(576+128)×2×1048576=33 GiB。这是按维度算出的对照，不是引擎的实测显存。 它说明稀疏选择本身不减少历史存储。

实际部署会量化缓存。本文固定版本的 vLLM NVIDIA 路径，主缓存 fp8_ds_mla 的内容是 512 字节 FP8 latent、4 个 FP32 scale，以及 64 个 BF16 共享 key，合计 656 B/token/层。默认 FP8 索引 key 是 128 字节数据加 4 字节 scale，合计 132 B。两者是 788 B，24 层、1M token 的内容大小约 18.47 GiB。主缓存写入、索引缓存格式

这个数不包含权重、KDA 状态、页面对齐、并行副本或临时工作区。也不能拿它与前面的 27 GiB 直接比较，然后说是 DSA 把显存压小了：两者使用了不同的缓存精度。索引缓存还可显式选择后端支持的 MXFP4 格式。权重量化、索引缓存量化和主 KV 格式分别配置，发布 MXFP4 权重不代表所有缓存都用 FP4。

其次，主注意力的候选数固定，不代表整段 prefill 变成线性复杂度。 对长度为 ttt 的可见历史，索引器仍需给历史 key 打分；只看点积，它约需 2×32×128×t2\times32\times128\times t2×32×128×t 次浮点运算。较昂贵的主注意力只访问 min⁡(2048,t)\min(2048,t)min(2048,t) 个位置。

因此可以分别写成：

部分单个 query 随历史长度的增长整段长度 nnn 的 prefill
索引器打分O(t)O(t)O(t)，32 头 × 128 维，低精度实现仍含 O(n2)O(n^2)O(n2) 个因果位置对
稀疏 MLA 核心O(min⁡(2048,t))O(\min(2048,t))O(min(2048,t))，另乘头数和维度常数O(n⋅2048)O(n\cdot2048)O(n⋅2048) 的上界

在 1048576 条可见历史的末端 query 上，2048 条占 1/512，约 0.195%。这是主注意力读取位置的比例，不是端到端提速 512 倍。索引打分、TopK、投影、MoE、KDA 和通信仍要执行；仅凭结构无法给出实际延迟。

能确认前向结构，不能据此补出训练配方

从配置与两套 serving 实现，现在可以确认：69 层 KDA + 24 层 Gated DSA；DSA 内是 32×128 的逐层独立索引器、top-2048、96 头 NoPE MLA，以及投影前的 sigmoid 输出门。 主干其余模块的结构配置沿用 K3。

但推理代码没有提供索引器的训练损失。DeepSeek 的 DSA 有自己的训练方法；同样使用 DSA，不足以证明 Kimi 使用相同的 KL 蒸馏、热身步数、冻结策略或数据量。为什么选 32 头、为什么 top-k 是 2048，也需要训练实验或消融才能回答。本文只解释这些选择在前向计算中意味着什么。

另一个边界是 MTP：公开配置的 num_nextn_predict_layers=0，所以图里不额外挂训练用的预测头；这个值也不能证明 K3.1 训练时从未使用 MTP。后续若有完整报告，可以再把这些空缺接上。
